## Prompt normalization — verified before the balanced trials

The native first-turn renderers originally differed: vBuf emitted 673 tokens / 2,881 characters, while llama.cpp emitted 672 tokens / 2,895 characters. The differences were the apostrophe escape in tool-schema JSON and llama.cpp's empty no-thinking suffix.

Without changing the evaluated vBuf path, a reproducible matched control was made from the chat template embedded in the identity-pinned GGUF. `make_matched_template.py` verifies the GGUF SHA-256, escapes apostrophes in tool schemas as vBuf does, and removes only the empty `<think>\n\n</think>\n\n` generation suffix. The resulting template hash is recorded in `raw/harness/qwen3-vbuf-matched-template.json`; the first Pi request body from excluded pilot `llama-01` is preserved as `template-probe-request.json`.

A probe-only llama-server run applied that template and tokenized the request, without running Pi or generating model output. `raw/template-probe/prompt-equivalence.json` records **673/673 identical token IDs** against the actual vBuf `vbuf-04` first-turn log (token-ID SHA-256 `24a4e6ecf08db8423782b0361aea6ae57eb4b6dc85a8e53125d1035559cdf05a`). The prompt fixture hashes match the checked-in system and user prompts. This resolves the first-turn prompt mismatch for the controlled comparison; each final trial must still retain its own prompt evidence. The probe establishes prompt identity, not agent success or numerical parity.

Pi's request does not specify `temperature`, `top_p`, or `seed`. llama.cpp is configured greedy (`temp=0`, `top-k=1`, `top-p=1`, `repeat-penalty=1`, seed 42); vBuf uses argmax. This is greedy-equivalent absent numerical ties. The final schedule uses a 12,288-token context on both backends and one server slot. Interpret results as a controlled **runtime-stack** comparison (including their output/tool protocol implementations), not as a pure kernel-only experiment.
