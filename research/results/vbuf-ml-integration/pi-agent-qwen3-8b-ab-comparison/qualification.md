# Experimental Qwen3-8B Pi coding-agent A/B qualification

## Decision

**Not qualified as an autonomous Pi coding agent on this task, on either backend.** All six pre-registered trials failed independent grading. The llama.cpp stack consistently delivered tool calls and generated the same source and Makefile, but that output failed the required strict C11 build and did not satisfy the behavioral-test contract. The vBuf stack consistently failed to parse the model's second tool response and generated no source. Pi exit code 0 is not treated as task success.

The experiment is a runtime-stack comparison, including prompt rendering, tool-call protocols, Pi's context budgeting, and backend behavior. It is not a kernel-only performance or numerical-parity test. Qwen3-8B remains experimental and identity-gated; these results do not change Qwen3-14B production settings, canonical packed-V AV authority, or numerical admission policy.

### Independent grading of llama.cpp outputs

All three llama runs generated byte-identical `snake.c` (9,309 bytes; SHA-256 `c73eb257f673b4c463ef876ca8c6fc0fb7569fb47c4e272dffe62ecd1348de13`) and Makefile (420 bytes; SHA-256 `901aa46faf9a8de246d21296061138a6920aa9370973574c4d9159ead023a26d`). Each was copied without edits to a separate grading directory and tested with `make test`. All three exited 2 before tests ran, with the same strict-build errors:

- `placeFood` and `isOccupied` are implicitly declared before use;
- `usleep` is undeclared under the requested strict C11 build with `-Werror`.

The source contains no `assert()` calls. Its self-test prints conditional pass/fail messages instead of failing reliably; the growth branch increments length without installing the new head; and the self-collision test is masked by the prior wall-collision state. Food-placement determinism/non-overlap and the requested line-at-a-time play behavior are not established. The README was the unchanged task fixture, so requested play instructions were not supplied there. The agent attempted repairs, but Pi's dynamically reduced request budgets ended late write calls with `finish_reason=length`; no successful test run followed.

### Interpretation and boundary

The llama.cpp path demonstrated functional enough tool calling to read, write, and run shell commands, but not a correct autonomous coding result. The vBuf path failed earlier at tool-output parsing in all three repeats, before source generation. Treat this as evidence about the compared runtime stacks and their current tool-output behavior—not as a claim that vBuf's compute kernels are less capable, nor as a pure compute-backend comparison.

Median trial wall time was 449.450 s for vBuf and 162.766 s for llama.cpp. These are descriptive end-to-end trial timings for unsuccessful runs, including startup, model generation, and tool handling; they are **not** throughput or performance qualification. No output was manually repaired or counted as agent success.
