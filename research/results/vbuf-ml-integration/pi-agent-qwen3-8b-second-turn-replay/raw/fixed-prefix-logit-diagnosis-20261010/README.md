# Fixed-prefix logit diagnosis evidence

This directory contains offline evidence for the Qwen3-8B second-turn generation investigation. It is diagnostic only; the binaries and capture instrumentation were temporary and did not alter the repository runtime.

## Inputs and indexing

- `second-request.json`, `rendered-prompt.txt`, `prompt-token-ids.csv`, `generated-token-ids.csv`, and `raw-generation.txt` preserve the exact request and original 6,144-token vBuf completion.
- The prompt has 916 tokens. Generated target index `j` is zero-based. For each captured target, the input is the 916 prompt IDs followed by generated IDs `[0, j)`. The saved token at `j` is not included in its own prefix.
- `positions.csv` lists all targets for which complete logit vectors were retained. `positions-first-divergence.csv` lists the short early-prefix capture.
- Every `.f32` file is one little-endian F32 vector of 151,936 logits (607,744 bytes), before sampling.

## Capture layout

- `vbuf/incremental/`: logits from one vBuf generation session, starting at the exact prompt and generating autoregressively. The 1,350-token bounded replay matched the original saved token sequence through its entire length.
- `vbuf/fresh-target-<j>/`: logits from a new vBuf session with the known prompt-plus-output prefix supplied as its prompt and one token generated. This changes prefill/decode shape and is not a cache-only control.
- `llama/`: llama.cpp logits from the matching GGUF and exact same fixed token prefixes. The context uses 12,288 tokens, batch 512, ubatch 128, flash attention disabled, and all layers on the RTX 3060. The pinned source checkout is commit `a97123e497968f3440264c0464a7adc7c999c027`.
- `llama/greedy-fixed-prefix-top1.csv`: top-1 prediction for all target indices 0–1,348, comparing llama.cpp against the saved vBuf token. The original file is retained as `greedy-fixed-prefix-top1.raw.csv`; its header newline was escaped by the temporary harness and was corrected offline in the companion CSV. No logit or row data was changed. The correction is reproducible with `python3 harness/fix_llama_top1_csv_header.py llama/greedy-fixed-prefix-top1.raw.csv /tmp/greedy-fixed-prefix-top1.csv`.
- `logit-comparison.json` and `logit-metrics.csv` are regenerated by the offline analyzer. `harness/analyze_fixed_prefix_logits.py` performs no model inference and requires NumPy.

## Reproduce the offline analysis

From the repository root:

```bash
python3 research/results/vbuf-ml-integration/pi-agent-qwen3-8b-second-turn-replay/raw/fixed-prefix-logit-diagnosis-20261010/harness/analyze_fixed_prefix_logits.py \
  research/results/vbuf-ml-integration/pi-agent-qwen3-8b-second-turn-replay/raw/fixed-prefix-logit-diagnosis-20261010
```

The C++ diagnostic sources and the temporary vBuf logit-capture patch are in `harness/`. The vBuf capture used an instrumented copy of `qwen3_generation.cpp` linked into a temporary archive based on the existing `/var/tmp/vbuf-qwen3-8b-ab-build`; the repository archive and runtime source were not modified. llama.cpp was used only as a fixed-prefix reference, not as an inference-path replacement.

## Scope and environment

Model identities and commands are recorded in `execution-manifest.json`; content hashes are in `artifact-sha256sums.txt`. Only logical CUDA device 0 (the RTX 3060) was visible to either inference process. The RTX 2080 SUPER workload was left untouched. The pre-existing listener on port 8080 was not used; the vBuf range source used an isolated loopback port and was stopped after capture.
